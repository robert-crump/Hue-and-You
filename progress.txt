## 2026-09-28 - Issue #40: Season palettes (12 fixed palettes)

New `colorspace/.../SeasonPalettes.kt`: `Season` enum (12 seasons) with `opposite` (the six
every-trait-flipped pairs from the issue), `PaletteCategory` (Neutrals, Lights, Mid-tones, Accents,
Darks) and `SeasonPalettes.best(season)` / `best(season, category)` / `avoid(season)` as ARGB ints.
Each season stores 20 Best hexes, 4 per category in category order. Avoid is derived: the first 2
of each category of the opposite season's Best, so within a category the leading colors are the
season's signature ones. Hex values are our own drafts from published season descriptions.

Test: `SeasonPalettesTest` covers 20 distinct colors, category order, opposite pairs/involution/trait
flip, Avoid derivation and no Best/Avoid overlap, plus an HCT sanity check (thresholds are test
constants): warm/cool hue arcs for chroma >= 12, Light tone >= 40, Deep Mid-tones/Accents tone <= 60
and Darks <= 22, Bright Mid-tones/Accents chroma >= 45 (sRGB caps turquoise near 50), Soft chroma
<= 40, Lights tone >= 70 and Darks <= 50 everywhere. Owner approved the private review page
(https://claude.ai/artifact/VeJmynxtsKVWtWgY8NsPfS). `./gradlew :colorspace:test` passes.

## 2026-09-28 - Issue #39: Add profile chooser bottom sheet

Settings -> Profiles "Add profile" now opens a `ModalBottomSheet` ("New profile") with two rows:
"Import color palette" (opens `PaletteImport` in new-profile mode) and "Choose custom colors" (the
old behavior: create a default-named profile and open its editor). The "Find my season" row is
omitted until #35 ships. The sheet hides before running the chosen action.

New-profile mode: the `PaletteImport` route is now `palette_import?profileId={profileId}` with a
`-1` default meaning "no profile"; `PaletteImportViewModel` takes `profileId: Long?` plus the
default profile name. With no profile, review uses the full 25 slots and `confirmImport` creates
the profile only then (so backing out creates nothing). Confirm moves to a new `Saving` state first
so a double tap can't create two profiles; `Done` now carries the target profile id. The NavHost
pops back for an existing profile, or navigates to the new profile's editor with `popUpTo` the
import screen (inclusive) so back returns to Settings. The review button reads "Create profile"
in new-profile mode. The review-start logic was split into `@VisibleForTesting startReview` so
tests can skip the Bitmap/marking steps.

Test: new `PaletteImportViewModelTest` covers full slots, nothing created without confirm, confirm
creating exactly one profile with the selected Best/Avoid colors, double confirm, and existing-profile
import. `./gradlew :colorspace:test :app:testDebugUnitTest assembleDebug lintDebug` all pass; not
tried on a device.

## 2026-09-27 - Issue #34: History rows - color summary line, long-press multiselect

Each History row gets a bodySmall summary line between the name and the date. Clothing:
`chosen | verdict`, verdict text colored by a new `SuccessColors.content` token (on-surface green;
`onContainer` was only legible on the green card), `error` for Avoid, `onSurfaceVariant` for
Ambiguous. Object: `chosen | complementary | analogous | tonal`, recomputed via
`HarmonyEngine.generate` from the entry's stored wheel/balance, Tonal only for a neutral color
(same rule as `HarmonyResultBody`). Circles are 12dp with a 1dp `outlineVariant` ring and are
drawn as plain Boxes, not `ColorCircle`, because that one always consumes click/long-press
(hex copy) and would steal the row's gestures. Object entries always have wheel/balance (detail
already `requireNotNull`s them), so a null just shows the chosen circle alone rather than
reading Settings defaults.

Trash icon removed in favor of Velometrics' Home selection pattern: long-press enters selection
mode, tap toggles, 0 selected stays in the mode with delete disabled. The contextual bar
(`X | N selected | delete`) is drawn by the NavHost (it owns the tab top bar), so `HistoryScreen`
reports `HistorySelectionBarState` up via `onSelectionChange`, like snackbar height. FAB is hidden
during selection; any bottom-nav tap, back or X exits. Selected rows get a `secondaryContainer`
tint and a check badge on the thumbnail. No confirm dialog: the undo snackbar was generalized
from one entry to a batch (`PendingDeletion.entryIds`, name only for a single entry, plural
"Deleted N entries" otherwise); a second delete takes over the snackbar while the earlier batch
finalizes on its own timer.

Test: `HistoryViewModelTest` now covers enter/toggle/exit selection, toggle-outside-mode no-op,
batch delete hide + exit selection, single-entry name, batch undo, batch finalize, and a second
delete replacing the undo target. `./gradlew :colorspace:test :app:testDebugUnitTest
assembleDebug lintDebug` all pass.

## 2026-09-27 - Issue #33: History detail - rename in the app bar, no scrolling

History detail's app bar title is now the entry name (1 line, ellipsis) with a pencil next to the
info icon; the "Name" text field and the fixed "Result" title (`history_entry_name_label`,
`history_detail_title`) are gone. The pencil swaps in `RenameTopBar`: X / an in-place
`BasicTextField` (`titleLarge`, primary underline, focused with the whole name selected) / tick.
Tick and IME Done save once; X and system back (`BackHandler`) discard. The tick is disabled while
the draft is blank. Draft + mode live in `rememberSaveable`. `HistoryDetailViewModel.rename` now
trims and ignores blank names (it no longer runs per keystroke). The body uses the live result
layout (photo `weight(1f)`, `maxHeightFraction = 1f`, no `verticalScroll`). Landscape/short screens
are split out to #36. Verified by `:colorspace:test :app:testDebugUnitTest assembleDebug lintDebug`,
not on a device.

## 2026-09-27 - Issue #32: Profile editor redesign (grids, edit mode, 25-color cap, hex-only add)

The Profile editor now shows Best/Avoid as 5-column grids of circles (no reorder arrows or per-row
remove icons), with a full-width tonal "Import palette from photo" button between the name field and
Best colors. Circle size comes from `worstCaseCircleSize` (two full 5x5 grids, 32-56dp), so it stays
stable as colors change; `verticalScroll` is kept only as a safety net. The pencil opens an edit mode
(X / "Edit colors" / tick) where tapping a circle with its "-" badge stages its removal in
`ProfileEditorViewModel`; the tick commits via the new batch `ProfileRepository.removeColors`, and
X or back discards. Reordering is gone (`MoveDirection`, `moveColor` and the unused DAO methods
deleted). Each list is capped at `MAX_COLORS_PER_KIND` = 25: `addColor` returns null when full, and
palette import pre-selects only the most dominant swatches that fit the remaining slots
(`preselectWithinSlots`/`toggleWithinSlots`) with an "n of m slots" counter. Existing over-cap lists
are kept and shown in full. Both add dialogs are replaced by a shared hex-only `HexColorDialog`
(filtered `#`-prefixed input, live preview, Add disabled until valid). Verified by
`:colorspace:test :app:testDebugUnitTest assembleDebug`, not on a device; `lintDebug` fails only on
the existing `CameraAdjustmentSliders` opt-in errors.
