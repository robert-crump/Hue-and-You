## 2026-09-30 - Issue #41: Camera pinch to zoom

Grilled with the user, spec written into the issue. The shared `CameraViewfinder` (so Rate
Clothing, Match Object and Find my season) zooms with `cameraControl.setZoomRatio`, so the capture
and its center box match the preview. New `ui/common/CameraZoom.kt`: pure `nextZoomRatio(current,
scale, max)` (clamped to 1x..`maxZoomRatio`, uncapped, never below 1x even with an ultra-wide) and
`Modifier.pinchToZoom`, which watches the Initial pass on the viewfinder Box: once a second finger
lands the gesture is consumed before the WB/exposure sliders see it (and stays consumed after one
finger lifts), while one-finger drags pass through. Zoom resets to 1x on every bind (lens switch,
new screen, retake). No reset gesture. A "2.3×" chip in the hint's style (`viewfinderLabel`) sits
above the shutter while pinching and fades 1s after release (`zoomActivity` counter re-triggers
it); it is a polite live region. TalkBack: the preview is a "Camera preview" node with custom
actions Zoom in / Zoom out (×1.5 / ÷1.5, same clamps).

Test: `CameraZoomTest` (multiply, 1x floor, device max, max below 1x, action round trip).
`./gradlew :colorspace:test :app:testDebugUnitTest assembleDebug lintDebug` all pass (lint: same
15 warnings); gesture, chip and slider handoff not tried on a device.

## 2026-09-28 - Issue #35: Find my season

Settings -> Profiles -> Add profile now has a "Find my season" row (first in the sheet) opening the
new `Destination.SeasonAnalysis` flow: `CameraCaptureStep` (now with `hint`/`showCenterBox` params;
the tip is "Daylight, no makeup, hair in view", no center box) -> tap step -> result -> "Create
profile" -> Profile editor (`popUpTo` the flow, so back goes to Settings). No History entry.

Tap step: pinch-zoom/pan photo (`ZoomablePickPhoto`, taps mapped back to bitmap pixels; markers and
labels drawn outside the zoomed layer so they keep their size), `FilterChip` row Skin/Hair/Eyes with
swatches, prompt per active chip, auto-advance to the next missing pick (wrapping; null once all set
until a chip is tapped), Next enabled at 3 picks. Sampling: `extractColorAtPoint` with 0.03 for
skin/hair and new `EYE_TAP_SAMPLE_RADIUS_FRACTION` 0.008 for eyes. The photo is decoded at up to
2048 px (other flows use 1024) so the iris sample covers enough pixels. Back/arrow: result -> taps
(picks kept) -> photo -> leave.

Classifier: `colorspace/SeasonClassifier.kt` (`SeasonAxes`, `SeasonTrait`, `Season.dominantTrait`/
`secondaryTrait`, `SeasonMatch.matchPercent`). Warmth = skin CIELAB hue angle (0.7) + hair chroma
projected on hue 60 deg (0.3, so ash/black read cool, golden/red warm); depth = per-feature L*
(hair 0.5, skin 0.3, eyes 0.2); clarity = hair-skin L* gap (0.6) + iris C*ab (0.4). Fit = dominant
+ 0.5 x secondary; match % maps -1.5..1.5 to 0..100. All centers/ranges/weights in
`CalibrationConfig` (SEASON_*), starting guesses. Note: with the 0.5 factor the fit ranking's top
is not always the pure "largest axis" pick (e.g. warmth 0.5, depth -0.49 -> Light beats Warm); the
fit formula from the issue was implemented as specified.

Result: picked swatches, top-3 rows (name, "NN% match", thin bar, radio-style selection), 20 Best /
10 Avoid preview grids (5 columns), Create profile (named after the season, deduped "Soft Autumn 2",
Best in category order then Avoid; `Saving` state guards double taps).

Test: `SeasonClassifierTest` (one reference Lab triplet per season, fit formula, clear-trait
ranking, opposite flips both traits, % mapping/clamp, axes in range); `SeasonAnalysisViewModelTest`
(tap sequence, re-pick, wrap, out-of-bounds taps, Next, top-3 + selection, back, create-on-confirm,
name dedupe, double confirm). `FakeProfileRepository` moved to `data/profile` in test sources for
reuse. `./gradlew :colorspace:test :app:testDebugUnitTest assembleDebug lintDebug` all pass; not
tried on a device.
